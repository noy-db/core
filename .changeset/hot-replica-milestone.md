**Hot replica, the pieces after keyring replication** (milestone "Hot replica": core#81, core#82, core#83).

- **Reserved-record replication is now a DECLARED set, not one collection** (core#83, core#82). After `_keyring`, three more travel through every sync target: `_meta/invite-audit-*` (the magic-link single-use evidence — `acceptInvite` on a fresh sync-peer device no longer throws `InviteAuditMissingError` once the issuer has pushed), `_users` (the directory's envelopes), `_delegations`. Ordering per rule: `roster_epoch` for keyrings, `_v` for the rest; the absent side receives; equal is a no-op. Written down and tested as NOT replicated: `_history` and `_ledger` (per-device evidence, a ledger is a hash chain per writer), `_sync`, and every other `_meta` id — `schema-fence` and the pod `handle` are session state and must never reach another device. `Vault.revokeDelegation()` now rides the dirty log so a revocation reaches the target on push and other devices on pull. Cost: one `list()` per rule per pull (four), none for `encrypt: false`.
- **A pulled change to YOUR OWN keyring file takes effect in the open session** (core#82). A re-grant that widens permissions is readable after the next `pull()`; no reopen. `Vault._reloadKeyringAfterSync()` is the seam.
- **`sync:progress`** (core#81): emitted during pull and push, throttled (25 records / 250 ms), `{ direction, phase, records, bytes, total? }`. For a pull the total is known once the remote snapshot is down, so progress measures the APPLY phase — the long one on an indexed store. `syncStatus()` and `syncTargetStatus()` gain `inFlight` for polling UIs. ⚠️ Not in this cut: a paged pull with bounded memory — it needs a way to enumerate a target's collections, which the store contract does not have; tracked on core#81.
- **`db.realign(vault)`** (core#82): a CORRUPTED local envelope keeps its `_v` and wins against the target's healthy copy on every pull. `realign` verifies every local user-collection envelope with the same `MergeAuthority` check pull runs on remote ones, replaces the failures from the target when its copy verifies, and drops the dirty log. Returns `{ checked, replaced, unrecoverable, errors }`. Repairs what the caller can read; a record at a tier the caller holds no key for passes unverified, as in pull.
- Not carried, by decision: `deleteUserEnvelope` is a free function without a vault, so a user-envelope deletion does not propagate (the create/update half does).
